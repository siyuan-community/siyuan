# 按需打包与发布准备

仅处理用户请求或已有授权覆盖的阶段。源码更新、普通提交、本地打包、发布标签和远端发布分别判断范围，不能因读取本参考自动串行执行全部阶段。

## 本地正式版标签

默认同步使用 `--no-tags`，通常没有新引入的官方标签需要清理。只有请求清理标签或已授权准备 CE 同名发布标签时才删除本地官方标签。

1. 有指定版本就只检查该版本。用户明确要求「最新正式版」时，按语义版本选严格匹配 `^v[0-9]+\.[0-9]+\.[0-9]+$` 的最大标签；不能只用 `v*.*.*` glob 或创建时间。预发布标签保持不动。
2. 用 `git rev-parse refs/tags/<版本标签>` 记录完整原对象，用 `git merge-base --is-ancestor '<版本标签>^{commit}' <已获取的官方masterSHA>` 核实归属。成功才确认在官方历史中；非零时区分「不是祖先」与引用不存在等错误，不能一律当作 CE 标签。
3. 属于 CE 的标签（包括尚未推送的本地发布标签）保持不动，不依据 origin 是否存在同名标签判断归属。属于上游时执行 `git tag -d <版本标签>`，只删除本地；报告原对象。需要恢复时可用 `git update-ref refs/tags/<版本标签> <原对象SHA>`。

不要执行强制标签获取、删除远端标签或修改 GitHub Release 来清理本地名称。继续获取上游时仍用 `--no-tags`，避免官方标签重新进入本地命名空间。

## 本地 macOS 包

用户明确要求本地打包（例如 `nu ./scripts/darwin-build.nu --target arm64`）时，授权覆盖该脚本实际调用的前端和 Go 构建；无需逐项重复询问。先核对当前脚本与用户要求的架构，不能默认从 arm64 扩成全部架构。

1. 检查是否存在开发 webpack 进程；若存在且会与生产构建冲突，请用户先停止，不自行终止。检查脚本会删除的目录是否包含需保留的产物：当前脚本清空 `app/build`、`app/kernel-darwin` 和 `app/kernel-darwin-arm64`。
2. 从仓库根目录运行请求的构建命令，保存日志并等到结束；不因进程启动或暂时没有日志就宣称成功。只停止自己启动且已识别的失败/废弃验证进程，不误伤开发服务。
3. 以退出码及本次新生成的产物核实成功。arm64 产物通常为 `app/build/siyuan-<版本>-mac-arm64.dmg`、对应 `.blockmap`、`app/build/mac-arm64/SiYuan.app` 和 `app/kernel-darwin-arm64/SiYuan-Kernel`；以实际脚本和 builder 配置为准。
4. 报告产物路径、大小和签名状态；日志出现 `skipped macOS application code signing` 时明确说明未签名。审查并报告构建中 `go mod tidy` 的差异，不自动回滚；`app/stage/build` 为生产产物，告知用户需要自行恢复开发构建。

## CE 发布提交与标签

只有明确授权发布准备或发布提交与标签时执行本节。若也授权远端推送/发布，沿用该授权；普通源码更新或「commit」不包含这些动作。

1. 核实前端版本、内核 `Ver`、用户请求版本及固定上游目标一致；不一致时先解决原因，不自行猜版本。版本一致不代表先前构建仍有效：构建后源码变化时报告产物与源码差异，不能当作同一已验证构建。
2. 确认合并已按授权提交。只暂存发布留下的已跟踪变化，按具体路径添加，例如 `kernel/go.mod`、`kernel/go.sum`；不把 `.agents/` 等无关未跟踪内容带入发布提交。审查 `git diff --cached -U6`。
3. 执行 `git commit -m ":bookmark: Release vX.Y.Z"`。无改动时，只有该发布提交本身已在授权范围内才用 `--allow-empty`；不跳过 hooks。已存在发布提交时先核实，不重复创建。
4. 检查同名标签。指向预期发布提交时视为已完成；指向其他 CE 提交时保留并报告，不自动移动。仍为上游标签时按上一节核实后清理，再执行 `git tag vX.Y.Z` 创建轻量标签。
5. 核对 `git rev-parse 'vX.Y.Z^{commit}'` 与发布提交 SHA、预发布标签和工作区。提交或标签之后再构建产生的变化不得自行 amend 或移动标签。
6. 汇报发布提交、标签 SHA、相对 origin 的领先数及已执行的构建/发布阶段。未经明确授权不推送；推送 CE 正式版标签会触发 `.github/workflows/cd.yml`，授权推送不等于可以宣称远端构建、测试或发布成功，仍须核实实际结果。
